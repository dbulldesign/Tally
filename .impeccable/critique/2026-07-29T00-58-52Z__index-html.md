## Design Specificity Verdict

Split product: the work surface is authored, the shell is category-interchangeable, and one feature is decoration.

Authored — could not be lifted into another product: the row grammar (pin · QTY · EXPRESSION · RESULT) with results in mono amber `#b4680f`, a carpenter's-brass rather than SaaS blue, applied with discipline to every number representing physical material; the pin-dot → black total-bar loop; Σ on a sticky section header; the entire Cut tab (`6 × 8′ 0″`, `run 45′ 0.64″`, `2′ 11.36″ left`, `20″ drop`, fill bars flipping good→warn above 40% waste, `FIXTURE ZONES → CHANNEL` as a distinct model); the phone syntax row; and the delete-worksheet copy.

Category-interchangeable: the whole shell — gradient titlebar with centred title and Light/Dark segmented control, toolbar strip, `···` menu, 224px sidebar with uppercase group labels, 300px 4-up pill tab bar. Rename the tabs and it is a design tool or a CRM. Project Map is pure filler: it shows only named lines, links only explicit `[Name]` references, renders one card on a full-screen dot grid in practice, and `exportData()` omits `map` so its only interaction is discarded on export — while holding a keyboard shortcut and two menu slots. The colour-dot rail added in 1.2.0 is conceptually right and executed as decoration: `addProject()` hardcodes `#0a84ff` and no UI sets a colour, so every worksheet renders an identical blue square.

Missed character: no `font-variant-numeric: tabular-nums` anywhere, so the RESULT column — the one place a takeoff sheet must form a scannable digit-aligned column — does not align. The engine parses `4' 6 1/2"` but the UI can only ever render `4′ 6.5″`, and there is no `/` key: a shop tool that cannot show sixteenths, spending its widest per-row text on `45.053333 ft 540.64″ 13.732256 m` instead.

Deterministic scan: the static CLI detector reports 0 findings, exit 0 (proved live by a canary file that correctly returned exit 2 on `font-family: Inter`). The in-page browser engine reports 14 findings at 1280, 16 at 900, 14 at 390 — an engine-capability gap, not a disagreement: everything the browser found depends on resolving CSS custom properties and cascade, which the static engine cannot evaluate. Of those, five were verified as false positives (hidden sidebar items at 390/900 where `.tsidebar` is `visibility:hidden` off-canvas; `.thead-cols` labels measured at 0×0 with `display:none` at 390; `clipped-overflow-container` on `.tshell`, which is the mechanism that clips the sliding sheet; `cramped-padding` on the version badge; monospace and the 11px secondary tier, both legitimate for measurement data). The real, reproducible findings are contrast and target size.

Visual overlays: injection succeeded — mutation preflight passed, the live server served detect.js (200, 367KB), and 14 overlay nodes with labels rendered in the page. But this runs headless with no display, so there is no browser tab you can look at; the overlay exists only in a captured screenshot. The live server was stopped and verified dead.

## Overall Impression

The measurement surface is the real thing — one colour rule, one gesture, one anchor, and a cut planner that could only exist in a fabrication shop. Then the app prints numbers that are wrong and offers no way to reach its primary action from a keyboard. That is the gap: this scores 18/40 not because it is ugly but because a tool whose output becomes a material order shows a total labelled `· @LA` that ignores the filter, and shows two different subtotals for the same section 700px apart in identical type. The single biggest opportunity is not visual: make every number the app displays defensible, then give the pin dot a keyboard path.

## What's Working

1. Amber as "measured quantity", applied with discipline to line results, section subtotals, label values, the total, cut-plan needs, the pin dot and the active Σ. You can scan a 500-line sheet for "what did this come to" without reading a word, and it makes Tally look like it belongs to a trade rather than to a SaaS template.
2. The phone syntax row: `' " × + # @ =` inserted via `pointerdown`+`preventDefault` so focus never leaves the field, lifted above the iOS keyboard by a `--kb` property from `visualViewport`. Real engineering aimed at one real problem — the two characters this product is built from are two keyboard layers deep on the device the audience holds.
3. Sticky section headers with live subtotals plus the Σ toggle: walking a 20-section job you always know which room you are in and what it has come to, and you can fold a room into the total with one tap. Takeoff-shaped, not a generic accordion.

## Priority Issues

**[P0] The filtered total shows an unfiltered number under a label that claims otherwise.** `TE.total()` is fed `comp.out` (all rows) while `totalLabel` appends `· @LA`; filtering happens later, only in the row list. Verified in code and live: filtering to `@LA` reads `SUM OF 3 PINNED · @LA` and displays `20′ 0″` when the @LA answer is `10′ 0″`. Why it matters: an estimator filters to a fixture type precisely to get that type's quantity, reads a number labelled with that type, and orders the wrong amount — with no way to catch it from inside the app. Fix: filter the rows fed to `total()` whenever `filter` or `search` is set, and scope `sectionTotals` identically; if you would rather not scope it, strip `· @LA` from the label and state `Total is not filtered`. Suggested command: `/impeccable harden`

**[P0] Nothing is reachable by keyboard except the text inputs.** Measured: 13 focusable elements, all `<input>`; 0 `<button>`, 0 `[role]`, 0 `aria-label`, 0 `aria-live`, 0 headings, 0 landmarks, no `lang` attribute; 68 elements carry `cursor:pointer` and are unreachable — including `.tcell-pin`, the app's primary action. Icon-only controls are named by `title` only; `.tsheet-x` has no name at all. Modals have no `role="dialog"` and no focus trap. Why it matters: a keyboard or screen-reader user cannot add a line to the running total — the task the product exists for is unavailable, not merely hard. Fix: give the clickable spans `role="button" tabindex="0"`, Enter/Space handling, and `aria-label` (move the `title` text there); `role="dialog" aria-modal` + focus trap on confirm, Settings, and both sheets; `aria-live="polite"` on the total; `lang="en"` on `<html>`. Suggested command: `/impeccable audit`

**[P0] Contrast fails systemically, from two shared tokens.** `--text3` is 2.51:1 light and 3.01:1 dark across seven surfaces (column headers, every result sub-line, the meta line, `new line…`, `TAGS`, the Σ glyph, the version badge). Placeholders are worse than assumed: no `::placeholder` colour is declared anywhere, so they render at Chromium's UA `#757575` — 4.19:1 light, 3.32:1 dark. Every error message is `#ff6b5e` at 2.79:1. `--warn` on cards is 2.06:1. `--amber` results are 4.26:1 at 15px/600 — fails AA. `#fff` on `--accent` is 4.02:1, theme-independent, on `Save`, `+`, `+ Line` and the active worksheet row. Dark mode passes the amber family but loses hierarchy: `--total #0e0e10` on `--bg #1e1e20` is 1.35:1 with no border, so the total bar dissolves into the page. Fix: raise `--text3` to ≈`#787880`, declare a `::placeholder` colour per theme, darken error red to ≈`#c8332a` light, darken `--amber` slightly or raise result weight/size, and give the dark total bar a hairline. Suggested command: `/impeccable colorize`

**[P1] Two disagreeing subtotals for one section, neither labelled.** `subMap` sums all length lines in a section; `secTot` sums only pinned ones. The section header shows the first, the total-bar chip shows the second — same name, same amber mono, ~700px apart, no label on either. Verified in code. Fix: make the header pinned-only so both agree (the Σ chip already governs pinned state), or label them `all` and `pinned`. Suggested command: `/impeccable clarify`

**[P1] Two open copies silently destroy each other's work, and the save status misleads.** The whole state blob is written to `tally:redesign` on a 400ms debounce with no `storage` listener, no writer id, no version counter, and no `beforeunload` guard (all verified: 0 occurrences). Tab 2's write overwrites tab 1's afternoon; tab 1 keeps showing stale content and loses it on reload. Reloading within the debounce window drops the last line. Meanwhile the sidebar says `Unsaved changes` when everything is autosaved, and after a reload says `No file yet — Export to save` beside a green dot. Why it matters: this is an installable PWA whose own `runMode()` comment anticipates several copies open; losing a takeoff with no error message is the worst outcome this product can produce. Fix: `storage` listener with a "changed in another window — Reload / Keep mine" bar, writer id + monotonic counter, flush on `visibilitychange`/`pagehide`, and status copy that distinguishes device-saved from exported. Suggested command: `/impeccable harden`

**[P1] The one path to the shop floor throws the work away.** `Print…` and `⌘P` are first-class actions with zero `@media print` rules (verified: 0). A 60-line worksheet prints as exactly one page — only the on-screen rows survive, wrapped in printed sidebar and toolbar chrome. Compounding it, the total bar's breakdown chips are uncapped: at 20 sections they occupy 220px, 28% of an 800px viewport, squeezing the worksheet to ~5 visible rows. Both failures scale with job size, where stakes are highest. Fix: a print stylesheet (`height:auto`, `overflow:visible`, hide the shell chrome, `break-inside:avoid` on sections, repeat column headers, print name + total + date); cap the breakdown to the largest four with `+16 more`. Suggested command: `/impeccable adapt`

## Persona Red Flags

**Alex (impatient power user — the persona the success metric is written for).** His first keystroke pattern, `12 + 3"`, meaning 15 inches, is rejected as `can't mix units` in near-invisible red, with nothing explaining that bare `12` is unitless. He taps the toolbar `+` and nothing visibly happens — the new row is appended off-screen and unfocused — so he taps it three more times before finding Enter. At 500 lines his typing degrades to 50–67ms per keystroke (932ms for eight characters into line 400) because every keystroke recomputes all 500 lines; a phone will be several times worse. `1/0` returns `Infinity` in the same amber as a real measurement, and it is pinnable into the total. The two things that genuinely serve him — `Paste as new lines` and ⌘D — are only discoverable by right-clicking empty space.

**Sam (screen reader, keyboard only).** Blocked at the primary action: tab order is text inputs then `BODY`; `.tcell-pin` is a bare span with a `title`. Nothing is announced back — no `aria-live` on the total, no `role="tablist"` on the inspector, section headers are not headings, and the page reports zero accessible names for its inputs. The app also removed the browser context menu everywhere and replaced it with a mouse-only menu, so the clipboard commands added to compensate are also out of reach. In the delete dialog: no `role="dialog"`, no focus trap (the focus ring stays on an input behind the scrim), Cancel and Delete are unfocusable spans, and Enter runs Delete — in an app where Enter is the most-pressed key.

**Riley (stress tester).** A 90-character `#Name` chip has no `max-width` and paints over the RESULT column, making the value illegible; same overrun in the Labels card and the sidebar tag list. `🚨 12" #🔥Emoji` returns `unexpected "?"` because the tokenizer indexes UTF-16 code units and splits the surrogate pair — the error message prints a replacement character. Typing then reloading 120ms later loses the line. Two tabs clobber. `((((` → `unexpected end`; `[Nope] + 5"` → `unknown "Nope"`. At 770px the empty-state hint truncates to `e.g. 4' 6"  #Rail`, silently cutting the half that teaches tagging.

**Casey (one-handed phone), the two elements that break for her:** the `.pdel` `×` sits permanently at `opacity:.55` on touch, 44px from the row she taps to switch worksheets, and deletes an empty worksheet with no confirmation and no undo; and the `Auto ▾` menu opens as a floating card anchored top-left — the farthest point from her thumb — while every other phone panel is a bottom sheet.

## Minor Observations

- Toolbar targets missed the 44px pass: `+` and `···` are 31×31, `+ Section` is 85×29, the `Auto ▾` chip is 66×36, and the search input is 31px tall. The row-level marks (pin, chevron, Σ, ✕, keys, action row) all measure exactly 44.
- `Zone —` prints an internal sentinel; `1 channels` and `1 pc` have no plural handling three functions away from a working pluraliser.
- `DEFAULT STOCK (UNTAGGED)` renders empty with no placeholder while the engine defaults to 96″ — the default is invisible.
- Quick calc is anchored `right:22px;bottom:22px` and therefore always overlaps the right end of the total bar, covering the two most important numbers on screen.
- Collapsed sections give no hidden-line count, and still contribute to the total; a collapsed empty section and a collapsed 40-line section look identical.
- Empty sections show a hard `0′ 0″` rather than a dash, reading as a computed zero.
- `Auto ▾` uses full names on the phone (`Feet + inches`, `Centimetres`) while the desktop control uses abbreviations for the same seven choices — the better labels are where there is less room.
- Two id schemes in one array: `addLine` uses sequential `nextId()`, `addSeparator` uses `genId()`, and `focusNext`'s selector depends on the sequential one.
- The version badge holds permanent prime real estate in the titlebar; it is already in Settings ▸ About.
- No `<link rel="manifest">` and no `theme-color`, despite the PWA framing and a working `sw.js`.

## Questions to Consider

1. What actually leaves this app? Capture speed is worthless if the artifact is a `.tally.json` nobody downstream can open and a print that drops 85% of the lines. If the honest answer is "a screenshot", the real primary action is not in this UI yet.
2. Why does an app that knows it is measuring material print `45.053333 ft`, while the engine can parse `4' 6 1/2"` and the UI can never show a sixteenth? Delete the sub-line and spend its space on fractions — the notation the audience writes on drawings.
3. What is Project Map for? If it vanished tomorrow, would anyone at the firm notice? It spends a shortcut, two menu slots and a full-screen surface, and does not persist its one interaction.
4. Why is there no undo in a product whose value proposition is not losing your place? One `⌘Z` over a snapshot ring would do more for confidence than the entire confirm-dialog layer — and would let you remove confirmations rather than add them.
5. Who are the second and third worksheet for? Either commit to the rail (auto-assign colours from the palette `migrateFile` already defines, add a swatch to the worksheet menu) or delete it and give the 46px to the expression column, which at 770px is squeezed to ~200px while a nearly-empty inspector holds 280px.
6. Is `Auto` a feature or a liability? It silently decides whether `540.64″` reads as `45′ 0.64″`, globally, with no per-line indicator — on a job mixing metric extrusion with imperial architecture, whose "auto" is it?
